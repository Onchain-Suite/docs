title: "Wallet and Contract Data"
description: "Enrich wallets with on-chain history and react to contract activity."
---

Everything Onchain Suite knows about a wallet comes from two places: on-chain data it reads for you, and events you send in. Here's how to use each.

## Enrich a wallet

Give the platform a wallet and a chain, and it fetches that wallet's portfolio, activity, and NFT holdings, then derives an engagement score and estimated LTV. Enrichment runs on its own (when a contact profile is opened, or when you save contract addresses in project settings) and can be refreshed on demand from your dashboard. See [Wallet Enrichment](/audience/wallet-enrichment) for the full behavior and the fields you get back.

Once a wallet is enriched, query the results in [SQL](/api/sql-schema), right next to your contacts and messaging data.

## React to contract activity

To message a wallet when it mints, swaps, or gets liquidated, build an automation with an on-chain trigger. For EVM contracts the platform watches the chain for you. See [Contract-Based Flows](/automation/contract-based-flows).

## Send product events

For activity in your own product rather than on-chain, [send a custom event](/integrations/custom-events):

```bash
curl -X POST https://api.onchainsuite.com/api/v1/events \
  -H "Authorization: Bearer sk_live_…" -H "Content-Type: application/json" \
  -d '{ "event": "first_deposit", "contact": { "walletAddress": "0xabc..." } }'
```

Every signal resolves to one wallet-first contact, so a segment or automation can combine "holds this NFT," "swapped last week," and "deposited yesterday" in one audience.
